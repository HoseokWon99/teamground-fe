# Teamground 발표용 프로토타입 구현 계획

- 발표일: 2026년 10월 12일
- 기준: `docs/screen-specification.md` v0.1
- 계획 작성 당시 저장소: 화면 명세서만 존재. 현재 구현 결과는 `docs/reports/integration.md` 참조
- 목표: 11개 화면을 연결하고, 일정 조율부터 영상 피드백까지 실제 클릭과 입력으로 시연
- 백엔드: 구축하지 않음. 인증·초대·캘린더 동기화·추천·저장은 모두 로컬 mock으로 대체
- 문서 상태: 구현 기준 계획. 2026-10-11에 11개 화면을 구현했으며 실제 검증 범위와 제한은 통합 보고서에 기록

## 1. 발표 범위와 임시 결정

명세서의 미정 사항은 아래처럼 프로토타입에 한해 가정한다. 실제 서비스 정책 확정을 뜻하지 않는다.

| 항목 | 발표용 결정 |
|---|---|
| 프론트엔드 | React + TypeScript + Vite, React Router. 배포 없이 로컬 실행 가능한 정적 앱 |
| 시각 방향 | 한국어 UI, 데스크톱 중심의 팀 작업 공간. 공통 사이드바와 팀 전환, 역할 배지, 충분히 읽기 쉬운 카드·표 |
| 인증 | 데모 계정 선택으로 로그인. 실제 OAuth 요청 없음 |
| 역할 | 관리자와 일반 멤버. 초대·일정 확정은 관리자에게만 제공 |
| 일정 입력 | 바쁜 시간 직접 등록 + 구글 연결·동기화 상태 시뮬레이션 |
| 일정 추천 | 매주 반복, 30분 단위, 모임 길이 30~240분, 탐색 기간 최대 8주, 당일 안의 탐색 시간대 |
| 영상 | 링크 등록. 발표 재생은 프로젝트에 포함한 사용 가능한 짧은 로컬 샘플 영상으로 보장 |
| 피드백 | 일반 텍스트 댓글, 최대 2,000자. 본인 항목 수정·삭제 |
| 영상 수정·삭제 | 피드백이 있으면 주소 수정 제한. 영상 삭제는 확인 후 연결된 피드백과 함께 로컬 삭제 |
| 초대 | 데모 초대 유효기간 7일. 발송은 로컬 초대 생성으로 대체하며 외부 이메일은 발송하지 않음 |
| 시간대 | Asia/Seoul. UTC 변환에 따른 날짜 이동이 없도록 날짜·시간 처리 공통화 |
| 제외 | 실제 서버·DB·메일·OAuth·구글 API·파일 업로드, 대댓글·타임코드, 팀 삭제·관리자 양도, 일정 수정·취소 |

공통으로 `데모 · 데이터는 이 브라우저에 저장됩니다`를 표시한다. 로그인·초대·구글 동기화 화면에는 해당 외부 연동이 시뮬레이션임을 추가로 표시한다. 화면상 권한 제어는 시연용이며 실제 서버 접근 제어를 구현한 것으로 취급하지 않는다.

## 2. 공통 기반과 mock 설계

### 앱 구성

예정 디렉터리 구조:

```text
src/
  app/          # 라우터, 앱 레이아웃, 로그인·팀 접근 가드
  components/   # 버튼, 필드, 모달, 상태 안내, 캘린더, 멤버 배지
  features/     # auth, teams, calendar, scheduling, videos
  mocks/        # seed 데이터, 서비스 함수, 데모 시나리오
  stores/       # 공유 상태, localStorage 저장·복원, 버전 관리
  lib/          # 날짜, 검증, 추천 계산
public/demo/    # 발표용 로컬 영상과 썸네일
```

- 화면에서 seed 배열을 직접 수정하지 않고 비동기 mock 서비스 함수를 호출한다.
- 서비스가 공유 상태를 변경하고 localStorage에 저장한다. 새로고침해도 생성한 팀·일정·영상·댓글을 유지한다.
- 데이터 버전을 저장하고 호환되지 않는 데이터는 안내 후 초기화한다. 저장소 접근 실패 시 메모리 모드와 안내를 제공한다.
- 읽기·쓰기 요청에는 짧은 지연을 적용해 로딩·저장 상태를 보여준다. 무작위 실패는 사용하지 않는다.
- 제출 중 버튼을 잠그고 확정·가입·등록 요청에 중복 방지를 적용한다.
- 접을 수 있는 데모 도구에 계정 전환, 시나리오 선택, 다음 요청 실패, 초기화를 제공한다. 초기화는 확인 후 실행한다.
- 브라우저 뒤로 가기, 상세 URL 직접 진입, 잘못된 ID와 다른 팀 접근도 처리한다.

### 공유 데이터 모델

| 모델 | 핵심 데이터 |
|---|---|
| User / Session | ID, 이름, 검증 이메일, 현재 로그인 사용자 |
| Team / Membership | 팀 ID, 이름, 설명, 사용자 ID, 역할 |
| Invite | 팀 ID, 대상 이메일, 토큰, 상태, 만료 시각 |
| PersonalEvent | 소유자, 제목, 시작·종료, 종일 여부, 수동·구글 출처 |
| CalendarStatus | 연결 상태, 마지막 동기화, 확인한 기간, 입력 완료 여부, 수정 버전 |
| SchedulingDraft | 팀 ID, 제목, 기간, 주기, 길이, 요일·시간대, 참석 조건, 필수 멤버 |
| Recommendation | 후보 시간, 회차별 참석 가능 정보, 생성 시각, 참조 데이터 버전 |
| Series / Occurrence | 정기 일정 묶음, 회차 ID, 일시, 확정 시 참석 가능 정보 |
| Video / Feedback | 회차 ID, 영상 ID, 제목·주소·등록자 / 본문·작성자·작성 시각·수정 시각 |

목록의 영상·피드백 수는 실제 연결된 데이터에서 계산한다. 사용자·팀·회차·영상 ID를 기준으로 필터링해 화면 간 데이터가 섞이지 않게 한다.

### 발표 seed와 시나리오

- 주 팀: `파동 극단`, 관리자 지우, 일반 멤버 하린·민서·도윤, 총 4명.
- 보조 팀: `프레임 영화팀`. 팀 전환과 데이터 분리 확인용.
- 초대 대상 신규 계정: 서연. 초대 이메일 일치·불일치 시연용.
- 초기 캘린더 표시 월은 2026년 10월로 고정하고, `오늘` 버튼은 실제 날짜로 이동한다.
- 예시 조율: `장면 리허설`, 2026-10-14~2026-11-06, 매주 2시간, 수·금 19:00~21:00, 전원 참석.
- 네 번의 수요일(10/14, 10/21, 10/28, 11/04)은 전원 가능. 금요일 2주차인 10/23에는 하린의 바쁜 시간을 배치한다.
- 기본 시나리오는 전원 일정 확인 완료. 샘플 팀 일정·영상·댓글도 별도로 넣어 각 화면을 즉시 열 수 있게 한다.
- `데이터 부족`: 하린의 일정 확인을 해제해 추천 불가 사유 표시.
- `후보 없음`: 필수 멤버의 바쁜 시간으로 모든 탐색 시간을 막는다.
- `확정 전 변경`: 추천을 연 뒤 필수 멤버 일정 버전을 변경해 재조회 안내.
- `오류`: 지정한 다음 저장·조회·동기화 요청만 실패시키고 재시도로 복구.
- 시나리오 전환은 영향 범위를 안내하며, 발표 시작 전 기본 상태로 초기화할 수 있게 한다.

### 추천 mock의 동작

고정 결과만 반환하지 않고 작은 로컬 계산 함수로 조건 변경을 반영한다.

1. 탐색 기간 내 선택 요일의 회차 날짜와 30분 단위 시작 후보를 생성한다.
2. 각 회차의 멤버별 바쁜 시간과 충돌 여부를 검사한다. 시작 포함·종료 미포함으로 비교한다.
3. 확인 범위 밖의 일정, 미완료 입력, 동기화 실패는 `확인 필요`로 처리한다.
4. 모든 회차에서 전원 또는 지정한 필수 멤버가 가능할 때만 추천한다. 미확인 필수 멤버가 있으면 데이터 부족을 표시한다.
5. 필수 멤버 방식은 전원 가능한 회차 수 → 참석 가능 인원 합계 → 첫 시작 시각 순으로 정렬한다. 전원 참석은 시간순이다.
6. 확정 직전 역할·멤버·일정 버전을 검사한다. 변경되었으면 재조회를 요구하고, 유효하면 전체 회차를 한 번에 저장한다.

## 3. 화면별 구현 plan

### AUTH-01 · 로그인·회원가입

- **경로:** `/login`
- **구성:** 서비스 소개, 데모 계정 선택, 로그인 버튼, 연동 시뮬레이션 안내.
- **동작:** 관리자·일반 멤버·초대 대상 계정으로 진입. 로그인 중 중복 클릭 차단.
- **Mock:** 선택 계정을 세션에 저장. 신규 계정도 가입이 완료된 상태로 처리. 초대를 자동 수락하지 않음.
- **연결:** 일반 진입은 `/teams`, 초대·보호 경로에서 왔다면 원래 경로 복원.
- **상태:** 인증 대기, 취소, 실패·재시도. 데모 도구로 실패 재현.
- **완료 기준:** 선택한 계정과 역할이 헤더에 반영되고, 초대에서 로그인하면 동일 초대로 복귀.

### INV-01 · 초대 확인·수락

- **경로:** `/invite/:token`
- **구성:** 팀명, 초대 이메일, 초대 상태, 현재 계정, 로그인·수락·팀 이동 버튼.
- **동작:** 비로그인 시 이메일 일부 마스킹. 로그인 후 이메일 일치 여부 확인. 수락 시 팀 멤버 추가.
- **Mock:** 유효·만료·무효·이미 수락·이메일 불일치 토큰을 준비. 생성한 초대 링크도 같은 데이터로 조회.
- **연결:** 로그인 후 복귀, 수락 후 해당 팀 홈으로 이동.
- **상태:** 잘못된 링크, 만료, 계정 불일치와 전환 안내, 이미 참여한 팀.
- **완료 기준:** 같은 초대를 여러 번 눌러도 멤버가 중복 생성되지 않고 팀 목록에도 즉시 반영.

### TEAM-01 · 내 팀 목록

- **경로:** `/teams`
- **구성:** 서비스 헤더, 팀 카드, 역할 표시, 팀 만들기 버튼, 내 일정 진입.
- **동작:** 팀 카드 선택, 팀 생성 진입, 계정 전환 시 해당 계정 팀만 표시.
- **Mock:** Membership으로 참여 팀 목록 생성. 기본 계정에는 서로 다른 데이터의 두 팀 제공.
- **연결:** `/teams/new`, `/teams/:teamId`, `/calendar`.
- **상태:** 로딩, 조회 실패와 재시도, 팀 없는 신규 사용자.
- **완료 기준:** 팀 생성·초대 수락 후 목록이 갱신되고 다른 팀의 데이터가 섞이지 않음.

### TEAM-02 · 팀 홈·일정

- **경로:** `/teams/:teamId`
- **구성:** 공통 사이드바, 팀명·역할, 일정 조율 버튼, 월 캘린더·목록 전환, 준비 상태 안내.
- **동작:** 월 이동·오늘 이동, 일정 선택, 지난 연습 조회, 팀 전환.
- **Mock:** 개별 회차를 캘린더와 목록에 함께 표시. 각 회차의 영상 수와 참석 가능 인원은 공유 상태에서 계산.
- **연결:** 조율 조건, 일정 상세, 멤버 목록, 내 일정.
- **상태:** 일정 없음과 첫 일정 조율 CTA, 일정 미확인 안내, 조회 실패.
- **완료 기준:** 추천 확정으로 생성된 모든 회차가 정확한 날짜에 표시되고 영상 추가 후 해당 회차의 수만 갱신.

### TEAM-03 · 팀 생성

- **경로:** `/teams/new`
- **구성:** 팀 이름·설명 필드, 만들기·취소 버튼.
- **동작:** 이름 공백 제거 후 1~50자, 설명 최대 200자 검증. 미저장 상태로 이탈 시 확인.
- **Mock:** 팀 ID를 생성하고 현재 계정을 관리자로 연결. 팀 이름 중복은 허용.
- **연결:** 생성 후 팀 홈과 멤버 초대 안내, 취소 시 내 팀 목록.
- **상태:** 필드 오류, 저장 중, 실패 시 입력 유지.
- **완료 기준:** 만든 팀에 관리자 권한으로 진입하며 새로고침 후에도 유지.

### TEAM-04 · 팀 멤버·초대

- **경로:** `/teams/:teamId/members`
- **구성:** 이름·역할·본인 배지, 관리자 전용 초대 버튼·초대 현황, 이메일 입력 모달.
- **동작:** 이메일 검증, 기존 멤버·대기 초대 중복 안내, 만료 초대 재생성, 데모 초대 링크 복사.
- **Mock:** 이메일 전송 없이 Invite 생성. 성공 문구는 `데모 초대가 생성되었습니다. 실제 메일은 발송되지 않습니다`.
- **연결:** 복사한 링크에서 INV-01 진입. 수락하면 멤버 목록과 초대 상태 갱신.
- **상태:** 일반 멤버에게 초대 관리 숨김, 저장 중, 실패 시 이메일 유지.
- **완료 기준:** 관리자만 초대를 만들고, 초대 링크에서 가입·수락하는 전체 흐름을 로컬에서 시연 가능.

### CAL-01 · 내 일정

- **경로:** `/calendar`
- **구성:** 개인 캘린더, 일정 추가 모달, 수동·구글 출처 배지, 구글 연결 카드, 확인 범위·입력 완료 버튼, 비공개 안내.
- **동작:** 직접 일정 등록·수정·삭제, 종일·날짜를 넘는 일정, 종료 시각 검증, 삭제 확인.
- **Mock:** 구글 연결을 누르면 샘플 캘린더 선택과 동기화가 진행됨. 로컬 샘플 이벤트를 추가하고 성공 시각 표시.
- **연결:** 팀 홈 또는 조율 조건으로 돌아가 새 추천 조회. 기존 조율 입력 유지.
- **상태:** 미연결·연결 중·연결 완료·재연결 필요, 동기화 실패·재시도. 구글 일정은 읽기 전용.
- **정합성:** 수정 시 입력 완료 상태 재확인. 연결 해제 확인 후 구글 이벤트만 제거. 추천 참조 버전 갱신.
- **완료 기준:** 본인 일정 변경이 추천에 반영되고, 팀 화면에 개인 일정 제목이 노출되지 않음.

### SCH-01 · 일정 조율 조건

- **경로:** `/teams/:teamId/scheduling`
- **구성:** 제목, 매주 반복, 모임 길이, 기간, 요일·시간대, 참석 조건, 필수 멤버 선택, 시간대 표시.
- **동작:** 필드 검증, 전원·필수 멤버 전환, `발표 예시 채우기`, 추천 요청.
- **Mock:** 팀별 조율 초안을 저장. 예시 버튼으로 seed의 4주·2시간·수/금 조건 입력. 예시를 서비스 기본값으로 간주하지 않음.
- **연결:** 추천 결과, 일정 확인 안내에서 내 일정·팀 멤버 화면.
- **상태:** 종료일 오류, 탐색 시간 부족, 필수 멤버 미선택, 일정 미확인 경고, 조회 실패.
- **완료 기준:** 결과에서 되돌아와도 조건이 유지되며 모든 입력 조건이 추천과 결과 요약에 반영.

### SCH-02 · 추천 결과

- **경로:** `/teams/:teamId/scheduling/results`
- **구성:** 조건 요약, 추천 카드, 회차별 참석 가능 표, 데이터 기준 시각, 조건 수정, 관리자 전용 확정 모달.
- **동작:** 후보 펼치기, 회차별 가능·불가·확인 필요 확인, 조건 수정, 선택 후보 확정.
- **Mock:** 공통 로컬 추천 함수 실행. 확정은 정기 일정과 회차들을 한 번에 생성하고 중복 요청 방지.
- **연결:** 조건 수정 시 입력 복원. 확정 후 첫 회차 상세. 조율 초안 없이 직접 접근하면 조건 화면으로 안내.
- **상태:** 계산 중, 후보 없음, 데이터 부족, 확정 전 일정 변경, 저장 실패. 일반 멤버에는 관리자 확정 안내.
- **완료 기준:** 기본 예시에서 수요일 4회만 추천. 하린이 불가능한 금요일은 제외. 변경된 추천으로 확정할 수 없음.

### SCH-03 · 일정 상세

- **경로:** `/teams/:teamId/occurrences/:occurrenceId`
- **구성:** 일정 제목·시간·시간대, 회차 표시, 확정 시 참석 가능 정보, 이전·다음 회차, 영상 카드, 영상 추가 모달.
- **동작:** 영상 제목 1~100자·주소 검증, 영상 등록, 회차 이동. 데모 영상 선택 기능 제공.
- **Mock:** 회차 ID에 영상 연결. 발표용 샘플은 로컬 재생 주소 사용. 일반 링크는 http/https만 허용하고 원본 열기 지원.
- **연결:** 영상 상세, 팀 캘린더. 이후 일정 변경이 있으면 확정 당시 정보와 현재 정보가 다를 수 있음을 표시.
- **상태:** 영상 없음, 잘못된 주소, 저장 실패, 존재하지 않는 회차, 다른 팀 접근 차단.
- **완료 기준:** 한 회차에 영상 A·B를 추가하고 각각 열 수 있으며 다른 회차에는 나타나지 않음.

### VID-01 · 영상 상세·피드백

- **경로:** `/teams/:teamId/occurrences/:occurrenceId/videos/:videoId`
- **구성:** 일정으로 돌아가기, 영상 제목·등록자·일시, 플레이어·원본 열기, 피드백 목록·입력, 본인 항목 메뉴.
- **동작:** 샘플 영상 재생, 피드백 등록·수정·삭제, 본인 영상 수정·삭제. 댓글 공백·2,000자 제한 검증.
- **Mock:** Video ID에 Feedback 연결. 저장 후 목록과 피드백 수를 갱신하고 입력 비우기. 실패 시 입력 유지.
- **연결:** 원래 회차 상세로 돌아가기. 영상 삭제 확인 후 연결 댓글 삭제와 회차 상세 이동.
- **상태:** 재생 불가 안내와 기존 댓글 유지, 댓글 없음, 저장 실패, 권한 없음·존재하지 않는 영상.
- **완료 기준:** A 영상의 댓글이 B에 표시되지 않음. 일반 멤버도 댓글 작성 가능하며 본인 항목만 수정·삭제 가능.

## 4. 구현 순서와 시간 배분

아래는 작업 시간 배분 목표다. 모든 화면을 연결하는 것을 기본 범위로 유지하고, 일정이 밀리면 고급 시각 효과와 확장 연동부터 줄인다.

| 순서 | 작업 묶음 | 예상 집중 시간 | 완료 산출물 |
|---|---|---|---|
| 1 | Vite 앱, 라우터, 공통 레이아웃·컴포넌트, seed·상태 저장·데모 도구 | 1~1.5시간 | 모든 경로의 기본 틀, 계정 전환·초기화 |
| 2 | TEAM-01·02, SCH-01·02·03, VID-01 | 3~4시간 | 일정 추천 → 확정 → 영상 → 댓글 전체 시연 |
| 3 | AUTH-01, INV-01, TEAM-03·04, CAL-01 | 2~3시간 | 로그인·팀 생성·초대·개인 일정 관리 연결 |
| 4 | 오류·권한·빈 상태, 반응형·키보드, 로컬 영상 확인 | 1~1.5시간 | 주요 예외 흐름과 좁은 화면 사용 가능 |
| 5 | 빌드, 핵심 검증, 발표 리허설 | 1시간 | 실행 안내와 재현 가능한 발표 상태 |

작업 시간이 부족하면 애니메이션, 풍부한 캘린더 편집 제스처, 외부 영상 임베드 서비스 확대를 생략한다. 핵심 버튼을 눌렀는데 아무 동작이 없는 상태나 화면별로 서로 다른 mock 데이터를 쓰는 상태는 남기지 않는다.

## 5. 발표 시연 순서

### 주 시연 · 약 4분

1. 데모 초기화 → 지우 관리자로 로그인 → 파동 극단 홈 진입.
2. 일정 조율 → 발표 예시 채우기 → 전원 참석 추천 조회.
3. 수요일 후보를 펼쳐 네 회차의 참석 가능 멤버 확인. 금요일이 제외되는 조건 설명.
4. 확정 모달에서 날짜 확인 → 확정 → 첫 회차 상세 진입.
5. 로컬 데모 영상 추가 → 영상 상세 → 재생 → 피드백 등록.
6. 팀 홈으로 돌아가 생성된 회차와 해당 회차 영상 수 확인.

### 보조 시연 · 약 2분

1. 팀 멤버에서 서연 이메일로 데모 초대 생성 → 링크 복사 → 서연 계정으로 수락.
2. 내 일정에서 바쁜 시간 추가 → 입력 완료 → 추천 반영 확인.
3. 필요할 때 데이터 부족 또는 저장 실패 시나리오 하나만 시연.

보조 시연으로 멤버·일정이 바뀌면 주 시연 재실행 전에 초기화한다. 브라우저 새로고침으로 상태가 지워지지 않는 것도 확인한다.

## 6. 발표 전 완료 체크

- [ ] 11개 화면의 주요 진입·뒤로 가기·상세 URL 접근이 연결됨.
- [ ] TypeScript 검사와 프로덕션 빌드 성공. 설치·실행 명령을 README에 기록.
- [ ] 추천 계산의 날짜 경계, 종료·시작이 맞닿는 일정, 네 회차 전원 조건, 확인 필요 처리에 의미 있는 단위 검증 수행.
- [ ] 기본 예시에서 수요일 4회 추천, 금요일 제외. 필수 멤버 선택 변경도 반영.
- [ ] 확정 전 데이터 변경은 재조회 안내. 연속 클릭으로 회차·영상·댓글이 중복 생성되지 않음.
- [ ] 초대 수락 전후의 팀 목록·멤버 목록·역할 일치.
- [ ] 일반 멤버의 초대·확정 제한과 다른 팀 상세 접근 차단 확인.
- [ ] 영상·피드백이 각각 해당 회차·영상에만 연결됨.
- [ ] 실패 시 입력 유지·재시도, 빈 상태와 오류 상태 구분.
- [ ] 1440px 데스크톱과 390px 좁은 화면에서 핵심 흐름 사용 가능. 모달 키보드 초점·복원 확인.
- [ ] 발표용 영상이 외부 네트워크 없이 재생되고 이미지·아이콘도 로컬에서 로드됨.
- [ ] 초기화 → 주 시연 → 새로고침까지 전체 리허설 완료.

이 문서는 최초 구현 계획이다. 앱 구현과 검증 결과는 `docs/reports/integration.md`를 기준으로 확인한다. 배포는 수행하지 않았다.
