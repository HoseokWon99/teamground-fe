# 인증·팀 화면 구현 보고서

담당: 병렬 에이전트 teams_auth

## 구현 범위

- AUTH-01: `/login` 데모 계정 선택, 로그인 중 중복 클릭 방지, 실패 후 재시도, 원래 내부 경로 복원.
- INV-01: `/invite/:token` 초대 조회, 비로그인 이메일 마스킹, 만료·무효·수락 완료·이미 참여 상태, 이메일 불일치 계정 전환, 수락 후 팀 이동.
- TEAM-01: `/teams` 본인 membership에 따른 팀 목록, 역할·멤버·일정 수, 팀 홈·생성·내 일정 연결, 로딩·빈 상태·실패·재시도.
- TEAM-03: `/teams/new` 이름 1~50자·설명 최대 200자 검증, 관리자 팀 생성, 실패 시 입력 유지, 제출 상태, 취소 확인과 새로고침/링크 이탈 확인.
- TEAM-04: `/teams/:teamId/members` 멤버 역할·본인·일정 확인 상태 표시, 관리자 초대 모달과 초대 현황, 기존 멤버 및 대기 초대 처리, 만료 초대 다시 생성, 초대 링크 복사와 직접 선택 대체 수단.

## 변경 파일

- `src/features/auth/pages.tsx`
- `src/features/auth/use-load.ts`
- `src/features/auth/login.test.ts`
- `src/mocks/service.ts`의 `login` 함수만: 선택적 AbortSignal 처리 추가
- `src/features/teams/pages.tsx`
- `docs/reports/teams-auth.md`

공유 store·서비스·라우터·스타일·컴포넌트는 담당 루트 에이전트가 제공하는 계약을 사용했다. `TeamHome.tsx`는 수정하지 않았다.

## 동작과 데이터

모든 변경은 비동기 mock 서비스로 수행한다. 폼은 React Hook Form + Zod를 사용한다. 팀 생성 후 해당 팀 홈으로 이동하면서 `{created: true}` 라우트 상태를 전달한다. 다른 멤버 로그인 이메일과 개인 일정 내용은 멤버 화면에 표시하지 않는다. 실제 소셜 인증과 이메일 발송은 없음을 화면에 표시한다.

로그인 복원 경로는 단일 `/`로 시작하는 내부 경로만 허용하고 프로토콜 상대 주소와 역슬래시 경로를 거부한다. 초대는 로그인과 별도 수락 단계다. 관리자 여부를 UI에서 확인하며 서비스의 권한 검사도 그대로 사용한다. 초대 정보 조회 실패는 무효 링크 상태와 구분한다.

## 실제 검증

- 관련 `AGENTS.md`, 화면 명세서, 프로토타입 계획 확인.
- `pnpm typecheck`: 공유 store 연결 후 성공.
- `pnpm build`: 초기 다른 담당 파일 미생성으로 실패했으나 최종 통합 후 다시 실행해 성공.
- `pnpm test src/features/auth/login.test.ts`: 로그인 취소가 기존 세션을 유지하고 다음 로그인이 성공하는 테스트 1개 통과.
- `vercel:react-best-practices` 체크리스트로 이벤트 정리, 파생 상태, 비동기 오류 처리, 필드 라벨과 상태 표시를 검토했다.
- 실제 브라우저 클릭·초대 수락·모바일 시각 검증은 이 보고서 작성 시점에 실행하지 않았다. 최종 통합 담당 검증 필요.

## 제한과 후속 확인

- 팀 생성의 취소·링크 클릭·새로고침 이탈은 확인하지만 브라우저 뒤로 가기에 대한 라우터 차단은 별도로 구현하지 않았다.
- 로그인 중 취소 버튼과 AbortController를 추가했다. 취소한 요청은 mock 서비스에서 세션 변경 전에 거절한다. 화면 이탈 시에도 요청을 취소한다. 취소를 실패 오류로 표시하지 않으며 요청 정리까지 제출 버튼을 잠가 중복 재시도를 막는다.
- 팀 생성 성공에 따른 초대 CTA는 팀 홈 담당이 전달받은 생성 상태를 사용하거나 기존 멤버 화면 동선으로 연결한다.
- 초대 유효 기간 및 중복 멤버 방지는 공통 mock 서비스 정책을 따른다.
- 클립보드 거부 환경에서는 링크 입력 칸을 선택해 직접 복사할 수 있다.

## 최종 검토

초대 이메일 비로그인 마스킹, 팀 membership별 목록, 일반 멤버 초대 관리 숨김, 서비스 오류 후 입력 유지 확인. 공통 Modal에 Dialog.Trigger가 없어 닫힐 때 초점 복원이 누락될 수 있음을 루트에 전달했고, 루트가 공유 컴포넌트 보완을 담당한다.
