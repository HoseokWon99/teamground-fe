# 계정 설정·서비스 탈퇴 UI

## 구현

- `src/features/server-workspace/Account.tsx`: `AccountPage` export. `/me` 조회, 표시 이름 수정, 계정 정보 표시, 탈퇴 화면을 구현했다.
- 표시 이름은 앞뒤 공백을 제거하고 Unicode code point 기준 1~30자로 검사한다. 필드 오류 시 입력에 초점을 맞춘다.
- PATCH는 현재 프로필의 version을 If-Match로 전송한다. 성공 응답으로 세션 표시 이름을 즉시 갱신한다. 실패 시 입력을 보존하고 412/428이면 최신 프로필을 명시적으로 조회한 다음 사용자가 다시 저장한다.
- 이메일·시간대·로그인 수단은 읽기 전용이다. 기존 공통 resource/action에서 401 세션 해제를 처리한다.
- 탈퇴는 Radix 기반 공통 Modal에서 `서비스 탈퇴` 문구를 입력해야 확정된다. 변경 요청 동안 닫기·중복 제출을 막는다. 미저장 이름은 기존 이탈 확인을 거친다.
- `/teamspaces`의 OWNER 팀을 확인하고 팀 관리 링크를 제공한다. 409 경합 응답은 팀 목록으로 안내하고 재조회한다.
- BE `AccountWithdrawalController`를 확인했다. DELETE `/me`는 CSRF만 필요하며 If-Match는 요구하지 않는다. 성공 시 세션과 인증 복귀 경로를 제거하고 `/login`으로 이동한다. 서버 데이터는 전역 영속 캐시 없이 컴포넌트 단위로 보관하므로 인증 화면 전환으로 해제된다.
- 모든 팀 이탈·개인 일정 삭제·캘린더 연결 해제·영상과 피드백 보존·작성자 익명 표시·재가입 시 권한 미복원 정책을 안내한다.

## 검증

- React best practices skill 검토: 조건부 Hook 없음, 독립 데이터 조회, 상태 변경은 이벤트 처리, 공통 접근성 모달·필드 안내·상태 메시지 사용.
- `pnpm typecheck`: 실행했으나 동시 구현 중 `ServerApp.tsx(125,68)`의 `TeamPage membersView` prop 미선언 때문에 실패했다. Account 파일의 진단은 없었다.
- `pnpm build`: 동일한 통합 타입 오류로 실패했다. 통합 담당자가 TeamPage 작업을 완료한 뒤 재실행해야 한다.
- QA 담당자에게 `/account`, 접근 가능한 label, 충돌 재조회 버튼, 탈퇴 문구 및 완료 URL을 전달했다. 브라우저와 실제 로컬 BE 검증 결과는 QA 통합 보고서를 기준으로 한다.
- 운영 계정 탈퇴는 실행하지 않았다.

## 후속 작업

- 통합 담당자의 라우팅·내비게이션 연결과 전체 타입 검사·빌드.
- QA의 390px·접근성·충돌·탈퇴 API 검증. OWNER 사전 방어를 우회하는 실제 409 검증은 소유권 변경 경합 또는 직접 로컬 API 호출로 재현한다.

## 통합 후 확인

초기 동시 작업의 타입 오류는 TeamPage props와 라우팅 연결 완료로 해결됐다. 통합 담당자가 2026-11-22 최종 `pnpm typecheck`, `pnpm test`(95개), `pnpm build`를 재실행하여 모두 통과했다. `/account`와 내 계정 메뉴를 연결했고, 소유 팀 관리 링크는 실제 관리 화면인 `/teams/:teamId/members`로 이동한다. 실제 로컬 BE의 프로필 변경·새로고침·소유 팀 탈퇴 차단·탈퇴 후 재로그인 거절 테스트도 통과했다. 전체 브라우저 최종 결과와 범위는 [03-verification.md](03-verification.md)를 기준으로 한다.
