# 실제 백엔드 브라우저 연동 검증

2026-11-22 · FE 전용 독립 QA 담당

## 환경과 실행 명령

- FE: `teamground-fe/.worktrees/backend-integration`, Chromium, Asia/Seoul.
- 실제 로컬 BE: `http://localhost:8080`, 테스트 SMTP/Mailpit: `http://localhost:18025`.
- 고유한 `integration-<timestamp>@example.test` 계정만 사용했다. 외부 사용자 메일, 운영 API 변경, OAuth 승인, 배포는 수행하지 않았다.
- 기존 이메일 인증 FE가 `[::1]:5173`을 사용하고 있어 해당 프로세스를 유지했다. 이번 worktree의 Vite는 `127.0.0.1:5173`에 별도 실행했다. Chromium의 `--host-resolver-rules=MAP localhost 127.0.0.1`로 브라우저 origin `http://localhost:5173`을 유지하며 새 worktree에 연결했다. 이는 로컬 허용 origin 검증이며 운영 CORS 통과 근거가 아니다.
- API 응답을 mock하거나 route interception으로 대체하지 않았다. 서버 쿠키·CSRF·If-Match와 실제 DB 저장을 사용했다.
- trace, screenshot, video는 껐다. 인증 토큰은 Mailpit에서 읽어 브라우저 메모리로 전달하며 파일에 저장하지 않았다.

```sh
pnpm dev --host 127.0.0.1 --port 5173 --strictPort
pnpm exec playwright test --config playwright.integration.config.ts
```

최종 결과: **1 passed (12.1s)**. 테스트 본문 실행 시간 11.5초. 앞선 전체 통과(11.4초) 이후 초대 서버 모드 우선 처리·권한 오류 시 데이터 제거·이탈 필수 멤버 필터의 최종 수정까지 반영한 상태에서 같은 명령으로 다시 통과했다.

## 실제 통과한 흐름

1. 이메일 가입 신청 → 테스트 SMTP 메일 → 인증 링크와 새 비밀번호 설정 → 실제 세션 로그인.
2. 팀 생성 → 서버 팀 목록에서 생성 ID 확인 → 팀 상세 접근.
3. 개인 바쁜 일정 저장 → 조회·입력 완료 범위 확인 → 팀 화면에 개인 일정 제목이 노출되지 않음.
4. 미래 기간·60분·수요일 18~19시 조건 저장 → 서버 추천 → 후보 선택 → 전체 회차 확정 → 첫 회차 접근.
5. 이탈 필수 멤버가 없는 일반 회차의 시각을 19~20시로 변경, 실제 PATCH **200** 확인.
6. HTTPS 원본 링크 영상 A 등록 → 피드백 작성 → 새로고침 후 서버 저장 내용 유지 → 원본 주소 수정 제한 → 피드백 수정 저장.
7. 같은 회차에 영상 B 추가 → A의 피드백이 B에 표시되지 않음.
8. 영상 B 화면에서 390×844 viewport의 핵심 제목 표시와 가로 넘침 없음 확인.
9. 개인 일정 편집 중 두 번째 클라이언트 요청으로 서버 버전 변경 → 기존 폼 저장 시 실제 **412** → 사용자 입력 유지 및 오류 안내 → 새로고침으로 최신 버전 조회 → 재입력·저장 성공.
10. 서버 세션 폐기 **204** → 새로고침 → 로그인 `returnTo` 경로 복귀 및 기존 개인 일정 데이터 미표시.

## 실패 원인과 재검증

- 최초 실행에서 개인 일정 저장 클릭이 요청을 보내지 않았다. 공통 Button 기본값이 `type="button"`인데 신규 폼 제출 버튼에 `type="submit"`이 누락되어 있었다. 구현 담당자가 신규 폼 제출 버튼들을 수정했고 최종 전체 흐름에서 통과했다.
- 회차 이동의 `requiredMemberIds`는 이탈 필수 멤버가 있을 때의 대체 입력이다. 루트 검토에서 일반 변경 요청에 이 값을 항상 보내는 문제를 발견했고, 수정 후 일반 회차 시간 변경 200을 실제 서버로 확인했다.
- 피드백 저장 직후 테스트가 textarea 입력값을 저장 결과로 오인하여 너무 빨리 새로고침하는 문제가 있었다. 저장 결과의 문단을 확인하도록 테스트를 수정했다.
- 개발 중 HMR로 편집 상태가 초기화된 실행은 최종 근거에서 제외했다. 소스 변경을 멈춘 뒤 재실행했다.
- 피드백 편집 textarea를 감싼 label의 텍스트에 초기값이 포함되어 `getByLabel(..., exact: true)` 탐색이 실패했다. 접근성 트리의 textbox 이름으로 찾도록 테스트를 수정했고 실제 편집·저장이 통과했다.

## 검증 범위의 한계

- 이 결과는 로컬 실제 FE·BE·SMTP의 핵심 흐름 검증이다. 운영 주소의 origin 허용, 운영 배포, 실제 사용자 메일 전달과 Google OAuth·캘린더 동기화는 검증하지 않았다.
- 이번 테스트에서 초대 수락·관리자 위임·다른 멤버 권한, 이탈 필수 멤버의 대체 선택, 팀 삭제·탈퇴, 회차 취소, 영상 회차 이동, 영상·피드백 삭제는 실행하지 않았다.
- 원본 링크 유형을 검증했다. MP4/WEBM 실제 재생과 외부 원본 서버 응답은 검증하지 않았다.
- 390px 검증은 영상 상세 화면에 한정한다. 전체 화면의 시각 검수나 전체 브라우저 호환성 결과로 확대 해석하지 않는다.
- 실제 BE 실행 프로세스의 정확한 빌드 SHA는 이 테스트에서 확인하지 않았다. 구현 담당자의 단위 테스트·타입 검사·빌드 결과는 별도 구현 보고서를 따른다.
