## 설계 검토

- 저장 warning을 구독 가능한 별도 상태로 분리하고 로그인 화면에서도 안내한다.
- 손상/미지원 데이터의 원본을 보존하는 동안 쓰기를 차단한다면, 영향 안내와 사용자 확인을 거친 복구 경로도 제공해야 한다.
- 개인일정·초대 및 확인 기간 입력은 기존 source별 전역 이탈 보호를 재사용한다. 원래 값을 저장한 뒤에는 불필요한 확인을 하지 않는다.
- 모바일 메뉴는 기존 Radix 모달 기반 초점 유지·Escape·복원을 재사용하고, 기존 라우트와 데스크톱 동작을 유지한다.
- 새 기능 범위를 늘리기보다 감사로 확인한 핵심 결함을 먼저 수정한다.

## 수정 요청과 반영 이력

1. 손상 원본 보존만 하고 저장이 영구 차단되는 상태를 피하도록 명시적인 복구 UI를 요청했다. 원본 대체·되돌리기 불가·미저장 폼 제외를 확인문에 명시하고 실패 시 모달 내부에 오류를 표시했다.
2. 복원 schema가 허용하는 음수 timezone offset을 `displayDate`가 처리하지 못하는 문제를 발견했다. suffix 판별 수정과 날짜 회귀 테스트를 추가했다. 실제 서비스 생성 데이터를 다시 복원하는 테스트로 유효 데이터의 과도한 거절도 확인했다.
3. 신규 StorageNotice를 App 바깥에 배치하면 데스크톱 고정 메뉴에 가릴 수 있어 로그인/초대의 PublicLayout과 인증된 Layout 안으로 배치를 나눴다. 독립 QA가 실제 버튼과 경고문 hit test로 가림 없음을 확인했다.
4. 일시적인 저장소 부재 후 API가 복귀할 때 읽지 못한 원본을 자동 덮어쓸 수 있는 경로를 발견했다. 부재도 읽기 실패와 같은 원본 보존 상태로 처리하고 명시적 복구 전후 회귀 2개를 추가했다. 정상 빈 저장소의 자동 저장은 유지한다.
5. 모바일 메뉴는 기존 모달의 초점 유지·Escape·복원을 재사용하고 메뉴 상태/대상 연결과 본문 건너뛰기를 추가했다. 개인일정·확인 기간·초대는 source별 dirty/saving 보호를 재사용하며 오류 설명을 필드에 연결했다.

저장소 담당 커밋 `16a162a`, 추가 수정 `d1766e2`와 UI 통합 `52b9b21`의 소스/테스트를 검토했다. 개발 중 HMR/전체 reload로 계측 모듈이 달라진 검사는 PASS에 포함하지 않고 파일 쓰기를 멈춘 새 5174 서버·새 브라우저 재실행 결과를 확인했다. 최종 검증에서 추가 앱 결함은 관측되지 않았다.
